# 模块架构设计 — 模型优化 (optimization)

> 所属项目：[MechGen 反无技战法生成模块](../CLAUDE.md)
> 总体架构：[总体架构设计](总体架构设计.md)

## 1. 模块定位

模型优化模块负责从基础模型到场景化可用模型的训练与演进。当检索模块发现无直接可用的模型时，优化模块制定优化方案、执行训练、完成模型转换，产出满足场景需求的新模型。

## 2. 后端设计（`modules/optimization/`）

### 2.1 API 路由

| 方法 | 路径 | 说明 | 独立可用 |
|------|------|------|---------|
| POST | `/api/v1/optimization/tasks` | 创建优化任务 | ✅ |
| GET | `/api/v1/optimization/tasks` | 查询优化任务列表 | ✅ |
| GET | `/api/v1/optimization/tasks/{id}` | 查询优化任务详情 | ✅ |
| POST | `/api/v1/optimization/config` | 生成优化配置建议 | ✅ |
| POST | `/api/v1/optimization/start` | 启动优化训练 | ✅ |
| GET | `/api/v1/optimization/status/{id}` | 查询训练状态（实时） | ✅ |
| POST | `/api/v1/optimization/convert` | 模型格式转换 | ✅ |

### 2.2 Service 层

```python
# modules/optimization/service.py

class OptimizationService:
    """优化业务逻辑 — 可被前端直接调用，也可被智能体通过 skill 调用"""

    async def create_task(self, req: CreateTaskRequest) -> OptimizationTask:
        """创建优化任务"""
        ...

    async def suggest_config(self, req: ConfigSuggestionRequest) -> TrainingConfig:
        """根据场景和模型推荐优化配置（超参、数据集、训练策略）"""
        ...

    async def start_training(self, req: StartTrainingRequest) -> TrainingStatus:
        """启动优化训练，返回初始状态"""
        ...

    async def get_status(self, task_id: str) -> TrainingStatus:
        """查询训练状态（进度、loss、指标）"""
        ...

    async def convert_model(self, req: ConvertRequest) -> ConvertResult:
        """模型格式转换（PyTorch→ONNX 等）"""
        ...
```

### 2.3 Schema 定义

| Schema | 字段 | 说明 |
|--------|------|------|
| `CreateTaskRequest` | model_id, scene, scenario_category, constraints | 创建优化任务请求 |
| `OptimizationTask` | id, model_id, scene, status, config, result, created_at | 优化任务实体 |
| `ConfigSuggestionRequest` | model_id, scene, constraints | 配置建议请求 |
| `TrainingConfig` | hyperparams, dataset, epochs, batch_size, lr_strategy, gpu_config | 训练配置 |
| `StartTrainingRequest` | task_id, config | 启动训练请求 |
| `TrainingStatus` | task_id, phase, progress, current_epoch, metrics, estimated_remaining | 训练状态 |
| `ConvertRequest` | model_id, source_format, target_format | 模型转换请求 |
| `ConvertResult` | model_id, target_format, output_path, validation_passed | 转换结果 |

### 2.4 数据模型

```python
# modules/optimization/model.py

class OptimizationTask(Base):
    """优化任务表"""
    __tablename__ = "optimization_tasks"

    id: Mapped[str]
    model_id: Mapped[str]                # 源模型ID
    scene: Mapped[str]                   # 目标场景
    scenario_category: Mapped[str]       # 侦测阶段分类
    status: Mapped[str]                  # pending/configuring/training/completed/failed
    config: Mapped[dict | None]          # 训练配置 JSON
    result: Mapped[dict | None]          # 训练结果 JSON
    created_at: Mapped[datetime]
    updated_at: Mapped[datetime]


class TrainingLog(Base):
    """训练日志表"""
    __tablename__ = "training_logs"

    id: Mapped[str]
    task_id: Mapped[str]                 # 关联优化任务
    epoch: Mapped[int]
    loss: Mapped[float]
    metrics: Mapped[dict]                # 评估指标 JSON
    timestamp: Mapped[datetime]
```

### 3.3 Skills

**hyperparameter-search**（`agents/optimization/skills/hyperparameter-search/SKILL.md`）：

```markdown
---
name: hyperparameter-search
description: 根据场景和约束推荐超参搜索空间
allowed-tools: execute read_file
---

# 超参搜索技能

## 触发场景
当需要制定优化方案、推荐训练配置时使用。

## 工作流程
1. 分析目标场景和约束条件（延迟、精度、资源）
2. 调用 optimization.config API 获取基础配置建议
3. 根据场景特征调整超参搜索空间
4. 输出推荐配置及理由

## 输出格式
返回 TrainingConfig，包含超参、数据集选择、训练策略和理由。
```

**distributed-training**（`agents/optimization/skills/distributed-training/SKILL.md`）：

```markdown
---
name: distributed-training
description: 配置和启动分布式训练任务
allowed-tools: execute read_file
---

# 分布式训练技能

## 触发场景
当需要执行模型训练时使用。

## 工作流程
1. 接收训练配置，调用 optimization.start API 启动训练
2. 定期查询 optimization.status 监控进度
3. 训练过程中发布 task_progress 事件到事件总线
4. 训练完成或失败时发布对应事件

## 输出格式
返回 TrainingStatus，包含最终指标和模型产物路径。
```

**model-conversion**（`agents/optimization/skills/model-conversion/SKILL.md`）：

```markdown
---
name: model-conversion
description: 执行模型格式转换和验证
allowed-tools: execute read_file
---

# 模型转换技能

## 触发场景
当训练完成的模型需要格式转换（如 PyTorch→ONNX）时使用。

## 工作流程
1. 确认源模型格式和目标格式
2. 调用 optimization.convert API 执行转换
3. 验证转换后模型的正确性

## 输出格式
返回 ConvertResult，包含输出路径和验证结果。
```

## 4. 事件发布与订阅

| 事件方向 | 事件类型 | 说明 |
|---------|---------|------|
| 发布 | `task_started` | 训练开始 |
| 发布 | `task_progress` | 训练进度（epoch、loss） |
| 发布 | `task_completed` | 优化完成，新模型可用 |
| 发布 | `task_failed` | 训练失败 |
| 订阅 | `task_completed` (module=collision) | 获取碰撞反馈，可能触发再优化 |

## 5. 与其他模块的协作

```
调用方：
  optimizer → retrieval.semantic_searcher  检索可用基础模型
  optimizer → trainer                      执行训练
  optimizer → converter                    模型转换

被调用方：
  collision.collision_coordinator → optimizer  优化后模型参与碰撞
```
