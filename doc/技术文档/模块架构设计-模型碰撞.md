# 模块架构设计 — 模型碰撞 (collision)

> 所属项目：[MechGen 反无技战法生成模块](../CLAUDE.md)
> 总体架构：[总体架构设计](总体架构设计.md)

## 1. 模块定位

模型碰撞模块负责多模型联合推理和规则沉淀。将多个优化后的模型进行碰撞推理，融合结果，提取结构化碰撞规则并沉淀入库，同时生成新的组合模型资产。

## 2. 后端设计（`modules/collision/`）

### 2.1 API 路由

| 方法 | 路径 | 说明 | 独立可用 |
|------|------|------|---------|
| POST | `/api/v1/collision/run` | 执行模型碰撞 | ✅ |
| GET | `/api/v1/collision/status/{id}` | 查询碰撞状态 | ✅ |
| GET | `/api/v1/collision/rules` | 查询碰撞规则列表 | ✅ |
| GET | `/api/v1/collision/rules/{id}` | 查询规则详情 | ✅ |
| POST | `/api/v1/collision/rules/deposit` | 沉淀碰撞规则 | ✅ |
| GET | `/api/v1/collision/history` | 查询碰撞历史 | ✅ |

### 2.3 Schema 定义

| Schema | 字段 | 说明 |
|--------|------|------|
| `CollisionRequest` | model_ids, collision_strategy, constraints | 碰撞请求 |
| `CollisionTask` | id, model_ids, strategy, status, result, created_at | 碰撞任务实体 |
| `CollisionStatus` | task_id, phase, progress, intermediate_results | 碰撞状态 |
| `CollisionResult` | task_id, fused_findings, confidence, new_model_id | 碰撞结果 |
| `CollisionRule` | id, name, trigger_conditions, conclusion, confidence, scene_tags | 碰撞规则 |
| `RuleDepositionRequest` | collision_task_id, rule_name, trigger_conditions, conclusion, confidence | 规则沉淀请求 |
| `RuleFilters` | scene_tag, detection_phase, min_confidence | 规则过滤条件 |
| `HistoryFilters` | status, date_range, model_ids | 历史过滤条件 |

### 2.4 数据模型

```python
# modules/collision/model.py

class CollisionTask(Base):
    """碰撞任务表"""
    __tablename__ = "collision_tasks"

    id: Mapped[str]
    model_ids: Mapped[list[str]]         # 参与碰撞的模型ID列表
    strategy: Mapped[str]                # 碰撞策略
    status: Mapped[str]                  # pending/running/completed/failed
    result: Mapped[dict | None]          # 碰撞结果 JSON
    created_at: Mapped[datetime]
    updated_at: Mapped[datetime]


class CollisionRule(Base):
    """碰撞规则表 — 碰撞推理沉淀的结构化规则"""
    __tablename__ = "collision_rules"

    id: Mapped[str]
    name: Mapped[str]                    # 规则名称，如 "同行+通信→高危"
    source_task_id: Mapped[str | None]   # 来源碰撞任务
    trigger_conditions: Mapped[dict]     # 触发条件 JSON
    conclusion: Mapped[str]              # 结论
    confidence: Mapped[float]            # 置信度
    scene_tags: Mapped[list[str]]        # 关联场景标签
    status: Mapped[str]                  # draft/validated/deployed
    created_at: Mapped[datetime]
    updated_at: Mapped[datetime]
```

### 3.3 Skills

**multi-model-inference**（`agents/collision/skills/multi-model-inference/SKILL.md`）：

```markdown
---
name: multi-model-inference
description: 编排多模型推理流程，管理推理依赖
allowed-tools: execute read_file
---

# 多模型推理技能

## 触发场景
当需要执行多模型联合推理时使用。

## 工作流程
1. 接收模型ID列表和碰撞策略
2. 调用 collision.run API 启动碰撞任务
3. 定期查询 collision.status 监控进度
4. 发布 task_progress 事件

## 输出格式
返回碰撞任务ID和中间推理结果。
```

```markdown

name: result-fusion
description: 融合多模型推理结果，处理冲突和置信度
allowed-tools: execute read_file
---

# 结果融合技能

## 触发场景
当多个模型的推理结果需要融合时使用。

## 工作流程
1. 收集各模型的推理结果
2. 识别结果冲突和一致点
3. 按碰撞策略融合结果，计算综合置信度
4. 生成碰撞发现

## 输出格式
返回融合后的碰撞发现列表，包含结论和置信度。
```

```markdown
# 规则提取技能

## 触发场景
当碰撞完成，需要从结果中沉淀可复用的规则时使用。

## 工作流程
1. 分析碰撞结果，识别可泛化的模式
2. 结构化提取规则：触发条件、结论、置信度
3. 关联场景标签
4. 调用 collision.deposit API 沉淀入库

```

## 4. 事件发布与订阅

| 事件方向 | 事件类型 | 说明 |
|---------|---------|------|
| 发布 | `task_started` | 碰撞开始 |
| 发布 | `task_progress` | 碰撞进度 |
| 发布 | `task_completed` | 碰撞完成，新规则/新模型可用 |
| 发布 | `task_failed` | 碰撞失败 |
| 订阅 | `task_completed` (module=optimization) | 优化完成后可启动碰撞 |
| 订阅 | `task_completed` (module=evaluation) | 评估结果反馈到碰撞策略 |

## 5. 与其他模块的协作

```
调用方：
  collision_coordinator → retrieval.semantic_searcher     检索碰撞候选模型
  collision_coordinator → inference_runner                执行碰撞推理
  collision_coordinator → rule_extractor                  提取碰撞规则
  collision_coordinator → evaluation.metrics_analyzer     评估碰撞产物

被调用方：
  optimization.optimizer → collision_coordinator  优化后模型参与碰撞
```
