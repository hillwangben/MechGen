# 模块架构设计 — 模型检索 (retrieval)

> 所属项目：[MechGen 反无技战法生成模块](../CLAUDE.md)
> 总体架构：[总体架构设计](总体架构设计.md)

## 1. 模块定位

模型检索是最基础的模块，为其他模块（优化、碰撞、评估）提供模型资产的发现和匹配能力。用户通过自然语言描述场景需求，智能体检索匹配的模型资产并给出推荐理由。

## 2. 后端设计（`modules/retrieval/`）

### 2.1 API 路由

| 方法 | 路径 | 说明 | 独立可用 |
|------|------|------|---------|
| POST | `/api/v1/retrieval/search` | 语义搜索模型资产 | ✅ |
| GET | `/api/v1/retrieval/models/{id}` | 获取模型详情 | ✅ |
| POST | `/api/v1/retrieval/match` | 评估场景与模型匹配度 | ✅ |

### 2.2 Service 层

```python
# modules/retrieval/service.py

class RetrievalService:
    """检索业务逻辑 — 可被前端直接调用，也可被智能体通过 skill 调用"""

    async def search(self, req: SearchRequest) -> list[SearchResult]:
        """语义搜索模型资产，支持三维分类过滤"""
        ...

    async def get_model(self, model_id: str) -> ModelAsset:
        """获取模型详情"""
        ...

    async def evaluate_match(self, req: MatchRequest) -> MatchEvaluation:
        """评估场景与模型的匹配度，生成推荐理由和不满足分析"""
        ...
```

### 2.3 Schema 定义

| Schema | 字段 | 说明 |
|--------|------|------|
| `SearchRequest` | query, detection_phase, model_form, maturity_level, limit | 搜索请求，支持自然语言查询 + 三维过滤 |
| `SearchResult` | model_id, name, score, detection_phase, model_form, maturity_level | 搜索结果条目 |
| `MatchRequest` | scene, scenario_category, constraints, candidate_model_ids | 匹配评估请求 |
| `MatchEvaluation` | model_id, match_score, recommendation_reason, gap_analysis | 匹配评估结果 |
| `Recommendation` | matched_models, unmatched_reasons, suggested_action | 综合推荐（满足/需优化/无匹配） |

### 2.4 数据模型

```python
# modules/retrieval/model.py

class ModelAsset(Base):
    """模型资产表 — 三维分类体系"""
    __tablename__ = "model_assets"

    id: Mapped[str]                      # 主键
    name: Mapped[str]                    # 模型名称
    description: Mapped[str]             # 模型描述
    detection_phase: Mapped[str]         # 侦测阶段（行动策划/人员集结/装备筹措/物流运输/临期准备）
    model_form: Mapped[str]              # 模型形态（基础模型/场景模型/组合模型）
    maturity_level: Mapped[str]          # 成熟度等级（L1-L4）
    version: Mapped[str]                 # 版本号
    framework: Mapped[str]               # 框架（PyTorch/ONNX/等）
    file_path: Mapped[str | None]        # 模型文件路径
    embedding: Mapped[bytes | None]      # 语义嵌入向量
    tags: Mapped[list[str]]              # 场景标签
    created_at: Mapped[datetime]
    updated_at: Mapped[datetime]
```

## 3. 智能体设计（`agents/retrieval/`）

### 3.1 智能体列表

### 3.3 Skills

**semantic-search**（`agents/retrieval/skills/semantic-search/SKILL.md`）：

```markdown
---
name: semantic-search
description: 构建搜索查询，调用检索API，排序筛选结果
allowed-tools: execute read_file
---

# 语义搜索技能

## 触发场景
当用户需要查找、发现、搜索模型资产时使用。

## 工作流程
1. 解析用户自然语言查询，提取关键语义要素（场景、阶段、约束）
2. 构造 SearchRequest，调用 retrieval.search API
3. 根据匹配度和用户意图排序结果
4. 如结果不足，尝试放宽约束或调整查询策略重新搜索

## 输出格式
返回候选模型列表，包含模型ID、名称、匹配分数和简要说明。
```

**match-evaluation**（`agents/retrieval/skills/match-evaluation/SKILL.md`）：

```markdown
---
name: match-evaluation
description: 评估模型与场景的匹配度，生成推荐理由
allowed-tools: execute read_file
---

# 匹配评估技能

## 触发场景
当用户需要确认模型是否满足场景需求，或需要推荐理由时使用。

## 工作流程
1. 如果未提供候选模型，先调用 semantic_searcher 检索候选
2. 构造 MatchRequest，调用 retrieval.match API
3. 综合匹配分数、推荐理由和不满足分析，生成最终推荐

## 输出格式
返回 Recommendation：满足的模型列表 + 不满足原因 + 建议行动（直接使用/需优化/无匹配需训练）。
```

## 4. 事件订阅

| 订阅事件 | 处理方式 |
|---------|---------|
| `task_completed` (module=optimization) | 更新模型资产索引，新优化模型可被检索 |
| `task_completed` (module=collision) | 更新碰撞产物模型索引 |

## 5. 与其他模块的协作

```
被调用方：
  optimization.optimizer    → 调用 semantic_searcher 检索可用模型
  collision.collision_coordinator → 调用 semantic_searcher 检索碰撞候选模型
  evaluation.report_generator → 调用 match_evaluator 评估模型匹配度

调用方：
  match_evaluator → 调用 semantic_searcher（内部协作）
```
