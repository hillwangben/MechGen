# 需求规范说明

## 文档组织

需求文档统一存放在 `doc/需求文档/` 目录下，按模块/主题拆分：

| 文档 | 内容 | 说明 |
|------|------|------|
| 项目总需求.md | 项目背景、目标用户、用户故事、业务结构、菜单目录、布局方式、主题样式 | 产品级需求全景 |
| 需求规范说明.md | 本文档 — 需求文档管理规范 | 元规范 |

## 加载优先级

当用户讨论功能时，Agent 应优先加载对应的需求文档，查看功能描述和约束条件：

1. **先查需求文档** — 理解功能的业务背景、用户故事和验收标准
2. **再查代码实现** — 以代码为事实依据，验证需求与实现的一致性
3. **文档仅供参考** — 需求文档可能存在滞后性，代码才是最终真相

## 文档与代码冲突处理

当需求文档与代码实现出现不一致时，遵循以下原则：

- **代码优先**：以最新的代码实现作为事实依据
- **记录差异**：在讨论中明确指出文档与代码的差异点
- **推动更新**：提醒用户是否需要更新文档以匹配代码

## 文档维护责任

- 用户和 Agent 需尽量保持文档与代码的一致性
- 功能发生重大变更后，建议同步更新对应的需求文档
- 新增功能时，优先补充需求文档再编写代码（文档驱动开发）
